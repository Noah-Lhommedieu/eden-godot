## S1 — Entités manquantes : diagnostic

Prouvé sur disque (`server_us/Data/db_decoded/`) :

- Justin Allspore = S_Monster id **58001** (+63910 variante Nightmare),
  Mori Mori = id **56459** — présents dans S_Monster.ini (12 896 records).
- Ces boss sont des **records 2 lignes** : `id|model|<Titre ＞\n`
  puis `nom|stats…` — `IniService.Records` les fusionne correctement
  (en-tête `|V.6|62|` → 63 champs).
- **Bug A** : `TranslationCatalog.Table` prend le 1er champ texte du
  record T_*.ini → pour `58001|<Earth's Relic> \nJustin Allspore|`
  le nom résolu = `<Earth's Relic>` → recherche "Justin"/"Mori" = 0
  hit. Fix : sauter les tokens `<…>` (titre) — prendre le 1er champ
  texte non-titre.
- **Bug B** : `ItemsViewModel`/`MonstersViewModel` plafonnent à **500**
  lignes (`if (++n >= 500) break;`) — 12 896 mobs : sans filtre on
  ne voit que les ~500 premiers ids. Fix : supprimer le cap +
  virtualisation + icônes lazy (ContainerPrepared).
- **Bug C** : `EntityIconIndex` utilise `Ini.Rows` (lignes physiques)
  → records multi-lignes mutilés/faux ids. Fix : `Ini.Records`.
- **Bug D** : `IniFilesViewModel.MaxShownRows = 1000` — même cap.
- Bug mineur : `ScrollViewer > ListBox` casse la virtualisation
  (mesure infinie → tous les containers réalisés) — retirer le
  ScrollViewer externe partout.
- Col2 des records boss = `titre\nnom` → afficher la dernière ligne
  pour le fallback Big5.
