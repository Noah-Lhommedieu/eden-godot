## Analyses tranchées (preuves)

### 1. Test de position de AttrGainCollectItem (vfunc +300)
- `CEC_AttrGainCollectItem::CanExecute` @0x085056b0 appelle `*(vtable+300)` sur le joueur ;
  si le retour est non nul → texte 0xe1c, sinon OK.
- vtable `lapis::CCharacter` @0x0888e5a0 (vptr = +8) ; slot +300 = 0x0840af50 =
  **`CCharacter::IsCoRiding()`**. Texte 3612 (`c_textindex`, Big5) = « 共乘中，無法進行此動作 »
  (« en co-monture, action impossible »).
- Conclusion : **le natif ne teste AUCUNE position dans cet effet**. 0xe1c = refus co-monture.
  La contrainte « dans l'aire » vient d'ailleurs (col32 de l'item `nodes;areaType`,
  contrôle d'usage non localisé). Le serveur C# (`ZoneEntryFlow.Items.cs` « aire + rayon + 2 »)
  reste une approximation, et envoie 0xe1c (faux texte) hors aire : à corriger quand le contrôle
  natif d'usage sera trouvé. Non modifié.
