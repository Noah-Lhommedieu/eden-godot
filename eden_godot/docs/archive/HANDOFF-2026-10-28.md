## Méthodologie qui a marché

1. **Lire** le point du plan, la référence visuelle (`ref-shots/*.png`),
   le layout natif et l'entrée du catalogue pour les fichiers utilisés.
2. **Préférer le layout natif** : `hud.Build("X.layout")` charge un
   layout CEGUI en contrôles Godot ; widgets retrouvés par nom
   (`TopLeftVitals.Find<T>(root, "Leaf")`, motif `*leaf*`, chemins `_`).
3. **Données** dans `data/db/` (Big5 : `iconv -f big5 -t utf-8 -c`) ;
   lignes multi-lignes par `\r?\n(?=\d+\|)`. Tables : `C_Class`/`T_Class`,
   `C_Talent`, `c_enchant`, `c_npc` (col 20 catégorie), `C_Level`/`S_Level`.
   `client-assets/data-db.md` décrit chaque table.
4. **Boucle de preuve visuelle** (obligatoire avant « fait ») :
   ```bash
   cd eden_godot && dotnet build godot_project/EdenClientReborn.csproj
   DISPLAY=:0 timeout 70 godot --path godot_project -- \
     --login=admin:adminmdp --channel --char --live \
     --hud-open=<cle> --shot=<chemin>.png > run.log 2>&1
   ```
   puis lire l'image et `grep -c "SCRIPT ERROR\|Exception" run.log` = 0.
   Options : `--hud-open=…`, `--class-tab=N`, `--class-test=<id>`,
   `--black-audit`, `--perf`, `--screen=login|channel|chars`,
   `--buff-test`, `--repair-test`, `--mob-test --combat-test`.
5. **Build + tests** : `dotnet build godot_project/EdenClientReborn.csproj`
   (0 erreur/warning), `dotnet test tools/NetTests` (414), serveur
   `cd eden_server/server && dotnet build Eden.sln && dotnet test` (1204).
   `scripts/data/*.cs` compilé aussi par NetTests : pas de `GD` ni
   `AssetCatalog` dedans (mettre dans `scripts/world/` ou `hud/`).
6. **Serveur modifié = le redémarrer** (`eden_server/bash
   start-native.sh`), sinon le live teste l'ancien binaire.
7. `git add -A` ajoute aussi les modifs de l'utilisateur : vérifier
   `git status` avant. Jamais deux clients Godot en même temps ;
   `re/` et `raw_assets/` en lecture seule.
